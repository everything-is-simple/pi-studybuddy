# studybuddy-task-complete

pi-studybuddy 受控任务收尾 Skill。

## 触发条件（三项必须同时满足）

1. `docs/04-Todo-List.md` 显示存在已获批准且正在执行的任务（状态 `in_progress` 或 `testing`）
2. 该任务对应的唯一 `.plan/T-XX-NNN-*.md` 计划文件中，所有验收项已完成
3. 用户在本次会话明确要求"完成"/"收尾"/"交付"该任务

**不满足任一条件 → 拒绝执行，告知用户原因**

## 执行流程（7 步，严格顺序）

### 步骤 1：复验测试和最小端到端路径

复验当前任务的：
- 单件测试（vitest + pytest，如涉及）
- 集成测试（如涉及）
- 系统冒烟（如涉及）
- 受影响 E2E（如涉及）
- 安全不变量校验脚本六条（如涉及）

**复验全过 → 进入步骤 2**
**复验失败 → 停止，告知用户失败原因，不进入收尾**

### 步骤 2：更新 docs/04-Todo

在 `docs/04-Todo-List.md` 中更新任务行：
- 状态改为 `done`
- 登记 evidence：
  - 测试通过证据（日志路径或截图）
  - 提交哈希（如已提交）
  - 推送状态（如已推送）
- 如有修复记录，写入 04-Todo §8 修复记录区

**禁止**：替用户预选下一项任务

### 步骤 3：创建实施记录

创建 `.record/T-<里程碑>-<序号>-实施记录.md`（如 `.record/T-M0-001-实施记录.md`）。

文件必须包含以下 8 章节（AGENTS.md §7.1）：

```markdown
# 实施记录：<task-id> <任务标题>

**任务 ID**：<task-id>
**日期**：YYYY-MM-DD
**计划文件**：.plan/<plan-file>.md

## 1. 任务裁决与范围
（做什么、不做什么、依据哪份设计文档）

## 2. 实际交付
（实际产出的文件/模块/测试）

## 3. 偏差
（与计划的差异，如有）

## 4. 问题及根因
（开发中遇到的问题及根因分析）

## 5. 关键决定及依据
（开发中的关键决策及权威依据）

## 6. 测试证据
（测试通过日志/截图/断言结果）

## 7. Git 证据
（提交哈希/分支名/合并记录/推送状态）

## 8. 未解决事项/下一步约束
（遗留问题、技术债、下一步约束）
```

### 步骤 4：更新 spec 文档（如 API 合同变化）

检查本次任务是否引起设计文档变化：
- API 合同变化 → 更新 `docs/06-API契约-API-Contracts.md`
- 数据模型变化 → 更新 `docs/05-数据模型-ERD-Data-Model.md`
- 工作流变化 → 更新 `docs/07-工作流-Workflow.md`
- 其他设计文档实质变更 → 走显式变更评审

**无变化 → 跳过此步骤**

### 步骤 5：标记完成状态

1. 在 `.plan/T-XX-NNN-*.md` 计划文件底部追加：
   ```
   ## 完成记录
   - 完成日期：YYYY-MM-DD HH:MM
   - 实施记录：.record/<record-file>.md
   - 状态：✅ 已完成
   ```
2. 保留该计划原件作为历史范围与验收证据（**不得删除**）
3. 该计划不再是后续施工指令

### 步骤 6：文档治理检查

运行 `scripts/check-docs-governance.mjs`（如已创建）：
- 文件名匹配 `^\d{2}-.+-[A-Za-z0-9-]+\.md$`
- 每份文档在 00-索引中登记
- 版本号一致性

**脚本未创建 → 手动检查文档治理**

### 步骤 7：停止并报告

向用户报告：
- 任务已完成
- 实施记录路径
- 04-Todo 已更新
- 文档治理检查结果
- **等待用户明确指示**

## 禁止事项（铁律）

1. **禁止创建下一任务启动 Prompt**——不预选、不预写下一任务
2. **禁止自动写生产数据库**——`%LOCALAPPDATA%\PiStudyBuddy\` 不写
3. **禁止自动提交/推送/合并**——必须用户在本次会话明确要求
4. **禁止以"任务完成"为由启动其他未选任务**
5. **禁止删除计划原件**——保留作为历史证据

## 中断恢复

如果收尾过程中断：
1. 读 `.plan/00-当前任务.md` 确认当前任务
2. 读 `.plan/T-XX-NNN-*.md` 的"完成记录"章节确认进度
3. 从未完成的步骤继续
