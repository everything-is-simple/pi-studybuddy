将本文件与一个 `T-M4-0xx-*.md` 任务提示词一并提供给执行 Agent。

```text
你是 H:\pi-studybuddy 的实施 Agent。仅在用户已明确选择并批准当前任务后，实施当前 task-id；不得因看到本提示词而假定已获开工或 Git 收口授权。

## 0. 权威入口与事实核验

严格按以下顺序读取：

1. AGENTS.md；
2. docs/00-文档索引-Index.md；
3. docs/04-任务清单-Todo-List.md；
4. .plan/00-当前任务.md（若存在）；

6. 上一项相关任务的 .plan/ 与 .record/；
7. 当前源代码、contract、handler、测试和真实 Electron E2E fixture。

先运行并报告：

- git status --short --branch
- git log --oneline --decorate -5
- git branch --show-current
- 任务在 docs/04、.plan、.record、master、origin/master 中的实际状态

不得依赖提示词中的静态进度快照覆盖实时仓库事实。发现上一任务尚未满足“04-Todo 证据 + master 复验 + origin/master 推送”时，停止业务施工并报告；不得跳过单一执行任务门禁。

## 1. 开工门禁

只有同时满足以下条件，才允许创建本任务唯一 `.plan/`：

- 上一任务已经完成并在 docs/04 登记；
- 用户已明确选择和批准当前任务；
- 当前任务即将进入实施；
- `.plan/` 没有其他 in_progress 计划；
- 工作区不存在无法识别归属的 dirty 修改。

开工后：

- docs/04：当前任务 pending → in_progress；
- .plan：创建唯一 `T-<milestone>-<id>-<scope>.md`；
- 分支：`agent/<task-id-lowercase>-<scope>`，遵守仓库实际分支命名；
- 测试运行根：`H:\pi-studybuddy-tmp\runs\<task-id>\`；
- 不得使用 git stash、git clean -fd、git reset --hard、git add -A 或 git add .。

## 2. 标准化开发过程

### A. 影响面审计

在写实现前输出：

- 权威条款 → 当前代码/contract/handler → 测试 ID 的追踪矩阵；
- 允许范围、非目标、风险和停止条件；
- 是否需要 API、handler、schema、AppShell 全局状态变化。

若需要新增 API、handler、schema、全局状态或改变已验收任务语义，停止并请求用户裁决。

### B. RED → GREEN → REFACTOR

严格执行：

1. **RED**：先创建与权威条款对应的失败测试；保存初次失败证据，不能通过删测试伪造全绿。
2. **GREEN**：只写让当前失败测试通过的最小实现；优先复用 typed RPC、useTabData、错误净化、课程/学期竞态防线、归档只读防线和已有 fixture。
3. **REFACTOR**：仅在测试全绿后整理状态、错误、空态、加载态、可访问性和重复操作防线；不得改变已验证行为。

每条关键不变量均记录：设计条款 → 测试 ID → fixture → 预期事件/RPC 序列 → 实际结果 → 日志/审计证据。

### C. 安全与隐私

始终满足：

- 仅 127.0.0.1，无真实外部服务；
- 测试不写 `%LOCALAPPDATA%\PiStudyBuddy`；
- renderer 不显示完整 UUID、API key、绝对路径、file URI、SQL、内部栈或敏感日志正文；
- 归档学期是只读：renderer 与 host 均需阻止写入；
- 异步请求有课程/学期切换、选择变更和组件卸载保护；
- mutation 需要重复点击/重复提交防线；
- 不提交资料原文、真实密钥、真实学生数据或运行数据。

### D. 定向与完整验收

先运行与本任务对应的 unit/integration/renderer/真实 Electron E2E 定向测试；通过后才进入完整质量门。

质量门前必须在同一个 PowerShell 进程执行：

$env:Path = "C:\node-v24.14.0-win-x64;$env:Path"
node --version   # 必须为 v24.14.0
pnpm --version   # 必须为 11.20.0

完整质量门至少包括：

- pnpm type-check
- pnpm build
- pnpm test
- pnpm smoke
- node scripts/verify.mjs --stage=full
- node scripts/check-docs-governance.mjs
- node scripts/check-contract-coverage.mjs
- node scripts/check-desktop-security.mjs
- UUID 泄漏专项检查（仓库已有脚本时）
- git diff --check

实际执行的命令、版本、测试文件/用例数量、E2E 数量、contract/security/smoke/UUID 结果和日志路径必须写入证据。

### E. 独立交叉审查

本地验收前至少两名独立审查者分别检查：

- scope 与未授权变更；
- RPC/contract 参数与返回值；
- renderer、preload、main、agent-host、handler 的真实链路；
- 竞态、卸载、归档只读、重复 mutation；
- 隐私、错误净化、UUID/路径/栈泄漏；
- 真实 Electron E2E 的代表性和 fixture 隔离；
- TDD 证据和质量门真实性。

P0/P1 必须修复并复验；记录两位审查者的独立结论和处置结果。

### F. 受控收尾

本地实施完成后：

1. 更新 docs/04 的任务状态、事实和测试证据；
2. 创建 `.record/<task-id>-实施记录.md`，必须有八章：任务裁决与范围、实际交付、偏差、问题及根因、关键决定及依据、测试证据、Git 证据、未解决事项/下一步约束；
3. 将 .plan 标记为已完成本地实施/验收，但保留原件；
4. 仅当 API 合同确有变化时才同步设计文档；
5. 运行文档治理检查；
6. 停止并报告。

没有用户单独的 Git 授权，禁止 commit、merge、push。没有用户选择，禁止启动下一任务。

## 3. 标准验收报告

6. 审查者 A/B 结论与 P0/P1/P2 处置；
7. docs/04、.plan、.record、API 文档的治理证据；
8. 未解决事项和需要用户继续授权的动作。
```
