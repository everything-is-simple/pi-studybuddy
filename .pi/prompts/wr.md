# /wr — Wrap it（任务收尾）

pi-studybuddy 任务收尾标准化流程模板。完成任务后按此模板执行收尾。

## 使用方式

```
/wr                    # 收尾当前 .plan/00-当前任务.md 指向的任务
/wr T-M0-001          # 收尾指定 task-id 的任务
```

## 执行流程

### 1. 确认任务

- 读取 `.plan/00-当前任务.md` 确认当前任务
- 或读取指定的 `T-XX-NNN` 任务
- 确认任务状态为 `in_progress` 或 `testing`

### 2. 复验测试

复验当前任务的：
- 单件测试（vitest + pytest）
- 集成测试（如涉及）
- 系统冒烟（如涉及）
- 受影响 E2E（如涉及）
- 安全不变量六条（如涉及）

**全过 → 继续**
**失败 → 停止，报告失败原因**

### 3. 更新 04-Todo

- 任务状态改为 `done`
- 登记 evidence（测试日志/提交哈希/推送状态）
- 修复记录写入 §8（如有）

### 4. 创建实施记录

创建 `.record/T-<里程碑>-<序号>-实施记录.md`，包含 8 章节：
1. 任务裁决与范围
2. 实际交付
3. 偏差
4. 问题及根因
5. 关键决定及依据
6. 测试证据
7. Git 证据
8. 未解决事项/下一步约束

### 5. 更新 spec（如有变化）

- API 变化 → 更新 06-API
- 数据模型变化 → 更新 05-ERD
- 工作流变化 → 更新 07-Workflow

### 6. 标记完成

- 在 `.plan/T-XX-NNN-*.md` 底部追加"完成记录"章节
- 保留计划原件作为历史证据（不删除）

### 7. 文档治理检查

运行 `scripts/check-docs-governance.mjs`（如已创建），或手动检查：
- 文件名规范
- 索引登记
- 版本号一致

### 8. 生成收尾报告

向用户报告：

```
## 任务收尾报告

**任务**：<task-id> <标题>
**完成日期**：YYYY-MM-DD HH:MM
**实施记录**：.record/<record-file>.md

### 测试证据
- 单件测试：✅ 通过（N 条）
- 集成测试：✅ 通过（N 条）/ — 不涉及
- 系统冒烟：✅ 通过 / — 不涉及
- E2E：✅ 通过（E2E-XX）/ — 不涉及
- 安全不变量：✅ 六条全过 / — 不涉及

### 文档更新
- 04-Todo：✅ 已更新（状态 done + evidence）
- 06-API：✅ 已更新 / — 无变化
- 05-ERD：— 无变化
- 07-Workflow：— 无变化

### Git 状态
- 当前分支：<branch-name>
- 未提交改动：有/无
- 提交哈希：未提交（等待用户授权）

### 下一步
- 等待用户明确指示是否提交/推送
- 不预选下一任务
```

### 9. 停止

**禁止**：
- 自动提交/推送/合并
- 创建下一任务启动 Prompt
- 自动写生产数据库

**等待用户明确指示**：
- "提交" → 执行 docs/10-开发规范 步骤 16
- "推送" → 执行 git push
- "继续下一任务" → 请求用户选择下一任务
