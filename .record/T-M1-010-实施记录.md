## 3. 偏差

### 3.1 E2E 框架：child_process.fork 替代 _electron.launch()

**计划**：vitest + Electron `_electron.launch()` 直接启动 Electron 窗口

**实际**：vitest + `child_process.fork` 启动 Node.js 22 子进程

**原因**：Electron 33 内置 Node.js 20，不支持 `node:sqlite` 模块（Node 22.3+ 才有）。`_electron.launch()` 启动的 Electron 主进程无法加载数据层（`process.getBuiltinModule("node:sqlite")` 返回 undefined）。

**影响**：
- E2E 不启动真实 Electron 窗口，改为 fork Node.js 22 子进程加载 `dist/` 编译产物
- 子进程注册全部 S1-S4 业务 handler（与生产 agent-host 同构）
- 通过 Node.js IPC（`process.send`/`process.on('message')`）驱动 RPC 调用
- **不降低测试价值**：E2E 仍验证真实数据层 + 真实业务 handler + 全链回归，仅 UI 渲染层不参与
- 08-Test v0.1.2 §6 已同步框架描述（vitest + Electron 启动）

### 3.2 test-main.js 使用 CommonJS 而非 ES Module

**计划**：test-main.mjs（ES Module）

**实际**：test-main.js（CommonJS）

**原因**：`child_process.fork` 加载 .mjs 文件时 `require` 未定义，无法加载 `dist/` 下的 CommonJS 编译产物。改用 .js 扩展名 + CommonJS `require` 加载。

### 3.3 PracticeResult 补 practiceAnswerId 字段

**计划**：不修改契约层和业务 handler

**实际**：`src/contract/types.ts` + `src/agent-host/handlers/s3/practice.ts` 补 `practiceAnswerId`

**原因**：E2E-03 错题归档需要 `practiceAnswerId` 作为 `mistakes.archive` 的参数。原 `PracticeResult` items 不含此字段，E2E 无法获取归档所需的 practice_answer_id。补字段后不影响已有测试（722 测试全绿）。

## 4. 问题及根因

### 4.1 `_electron.launch()` is not a function

**现象**：计划用 Electron 的 `_electron.launch()` 启动窗口，但该 API 不存在。

**根因**：`_electron.launch()` 是 Playwright 的 Electron 测试 API（`@playwright/test`），不是 Electron 原生 API。项目未安装 Playwright。

**修复**：改用 `child_process.fork` 启动 Node.js 子进程。

### 4.2 `node:sqlite` 在 Electron 环境不可用

**现象**：子进程启动后 `process.getBuiltinModule("node:sqlite")` 返回 undefined，数据层初始化失败。

**根因**：Electron 33 内置 Node.js 20，`node:sqlite` 是 Node.js 22.3+ 实验性模块。Electron 的 Node.js 版本太低。

**修复**：改用系统 Node.js 22（`child_process.fork` 默认使用 `process.execPath`，即系统 Node.js），不依赖 Electron 内置 Node.js。

### 4.3 RPC 超时 Promise 未正确 reject

**现象**：RPC 调用超时后，Promise 未被 reject，测试卡住。

**根因**：`setTimeout` 回调中直接 `throw new Error()` 无法被 Promise 捕获。

**修复**：在 `setTimeout` 回调中调用 `entry.reject(new Error(...))` 并从 `pending` Map 中删除条目。

### 4.4 vitest.e2e.config.ts 语法错误

**现象**：vitest 加载 E2E 配置时报语法错误。

**根因**：注释中包含 `**/` 被解析为块注释结束符。

**修复**：修改注释文本避免 `*/` 序列。

## 5. 关键决定及依据

### 5.1 E2E 框架：child_process.fork + Node.js IPC（非 Playwright，非 _electron.launch()）

**决定**：vitest + `child_process.fork` + Node.js IPC

**依据**：
1. 08-Test §1.3 第 6 条"不连真实外部服务"是铁律——E2E 本质是"真实数据层 + mock 外部服务"
2. pi-desktop 范式：`scripts/test-browser-agent-e2e.mjs` 用子进程 + assert
3. AGENTS.md §6.4 禁止过度工程化：不引入 Playwright 依赖
4. `node:sqlite` 兼容性：Electron 33 Node 20 不支持，系统 Node 22 支持
5. vitest 已就绪：不新增 devDependencies

**权衡**：牺牲 UI 渲染层断言，保留数据层全链回归 + 安全不变量断言。

### 5.2 防泄露铁律：assertNoLeakage 双重检查

**决定**：字段黑名单 + JSON 序列化文本扫描双重检查

**依据**：08-Test §7.2 防泄露铁律。仅查字段名不够——答案可能藏在嵌套结构或序列化文本中。

### 5.3 薄弱点形成条件：evidence_count≥2

**决定**：E03-10 验证 evidence_count=1 时不形成薄弱点，E03-12 验证 evidence_count≥2 时形成

**依据**：08-Test §7.3 证据驱动。单次错误不形成薄弱点，需累计证据。
