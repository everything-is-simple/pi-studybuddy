## 4. 问题及根因

- **JSDoc 注释解析**：测试文件 JSDoc 标题含 `credentials.*/settings.*` 的 `*/` 被解析为注释结束符。修复：改为 `credentials + settings`。
- **Windows EBUSY**：global.db 文件被 SQLite 句柄占用时 rmSync 失败。修复：safeRmSync 忽略清理错误（Windows 文件锁特性，测试已断言功能正确）。

## 5. 关键决定及依据

1. **数据根初始化落 main 进程**：依据 03-Arch §6.2 main 进程职责（窗口/协议/数据根），agent-host 是 utilityProcess 不负责首次建库
2. **createBusinessHandlers 复用 extension 上下文模式**：依据 03-Arch §6.2 agent-host 承载业务内核 RPC 服务，上下文创建模式与 studybuddy-extension.ts 一致（S*Context 句柄管理）
3. **settings 落业务数据根 config/settings.json**：依据 AGENTS.md §9.5 物理隔离（pi-studybuddy 不侵入 ~/.pi）+ 03-Arch §4.5 数据层落点
4. **credentials handler 封装 CredentialVault**：依据 03-Arch §4.5 + T-M0-003 已实现 safeStorage/DPAPI，handler 层仅做 RPC 适配
5. **三任务合并收尾**：T-M4-001/002/003 是同一批后端断裂修复（断裂 1/4/5），代码紧密关联（main.ts 初始化 → agent-host 装配 → credentials/settings handler），合并登记 + 合并实施记录
