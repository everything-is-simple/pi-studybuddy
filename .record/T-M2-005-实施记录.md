## 3. 偏差

### 偏差 1：zip 实现从"Node 内置 zlib"改为"手写最小 zip 格式"

**计划**：用 Node 内置 zlib 实现 zip 打包/解包。
**实际**：Node 内置 zlib 只提供 deflate/inflate，不处理 zip 容器格式（local file header + central directory）。手写最小 zip 格式（packZip 写 local header + central directory + EOCD；unpackZip 解析 central directory 逐条 inflate）。
**原因**：zip 是容器格式，zlib 只处理压缩算法层。不引入 adm-zip 等外部依赖（AGENTS.md §6.4 直接套库 vs 套组件配薄胶水原则，zip 格式简单可手写）。
**影响**：无负面，零外部依赖，zip 炸弹防护在 unpackZip 层直接实现。

### 偏差 2：新增 lookup.ts 和 zip.ts 两个文件（计划未列出）

**计划**：文件清单列出 9 个 src 文件。
**实际**：新增 lookup.ts（跨库查询 findSemesterByCourseId）和 zip.ts（packZip/unpackZip 工具函数），共 10 个 src 文件。
**原因**：zip-packer/zip-restorer 共用的 zip 读写逻辑提取到 zip.ts；backup.ts 共用的跨库查询提取到 lookup.ts，职责分离更清晰。
**影响**：无负面，代码结构更清晰。

### 偏差 3：restore 导入用 PRAGMA foreign_keys = OFF/ON 包裹

**计划**：导入顺序按表依赖关系。
**实际**：导入前 `PRAGMA foreign_keys = OFF`，导入后 `PRAGMA foreign_keys = ON`，避免导入顺序依赖。
**原因**：jsonl 导入是批量操作，按表依赖关系排序复杂且脆弱。临时关闭外键约束后重开是 SQLite 官方推荐的数据导入模式。
**影响**：无负面，导入后 integrity_check 保证数据一致性。

## 4. 问题及根因

### 问题 1：semDb.pragma is not a function

**现象**：zip-restorer 调用 `semDb.pragma("foreign_keys = OFF")` 报错。
**根因**：node:sqlite 的 DatabaseSync 没有 `.pragma()` 方法（那是 better-sqlite3 的 API）。
**修复**：改用 `semDb.exec("PRAGMA foreign_keys = OFF")` 和 `semDb.prepare("PRAGMA integrity_check").all()`。

### 问题 2：content_hash 校验失败

**现象**：恢复时 computedHash !== manifest.content_hash。
**根因**：manifest 生成时 total_size_bytes 在 content_hash 之后计算，导致 manifest.json 内容不一致。
**修复**：调整 manifest 生成顺序，先计算 total_size_bytes 再计算 content_hash（content_hash 排除 manifest.json 自身）。

### 问题 3：normalized_texts 表无 updated_at 列

**现象**：导入 jsonl 时报 "table normalized_texts has no column named updated_at"。
**根因**：05-ERD §3.2.2 normalized_texts 表无 updated_at 字段，但导出时错误包含了该字段。
**修复**：移除 normalized_texts insert 语句中的 updated_at 列。

### 问题 4：zip 炸弹检测未触发

**现象**：超大解压比测试用例未抛 ZIP_BOMB_DETECTED。
**根因**：unpackZip 初版只检查条目数，未检查解压后总大小与压缩后大小比例。
**修复**：在 unpackZip 中累计解压后总字节数，与压缩后字节数比较，超过 100:1 比例抛 ZIP_BOMB_DETECTED。

## 5. 关键决定及依据

### 决定 1：手写最小 zip 格式，不引入外部依赖

**依据**：AGENTS.md §6.4 组件粒度原则 + §9.4 组件安全。zip 格式简单（local header + central directory + EOCD），Node 内置 zlib 提供 deflate/inflate，无需 adm-zip 等第三方库。手写可完全控制 zip 炸弹防护和路径遍历防护。
**实现**：zip.ts packZip 写 zip 格式（每个条目 local file header + deflated data + 末尾 central directory + EOCD）；unpackZip 解析 central directory 逐条 inflate。

### 决定 2：content_hash 排除 manifest.json 自身

**依据**：content_hash 用于校验备份完整性，manifest.json 包含 content_hash 字段本身，不能自引用。
**实现**：先计算所有 data/*.jsonl + storage/* 文件的 SHA-256 聚合哈希，再写入 manifest.json 的 content_hash 字段。恢复时重新计算（排除 manifest.json）并比对。

### 决定 3：restore 临时关闭外键约束

**依据**：SQLite 官方文档推荐批量数据导入时临时关闭外键约束。导入后 PRAGMA integrity_check 保证数据一致性。
**实现**：`PRAGMA foreign_keys = OFF` → 导入 jsonl → `PRAGMA foreign_keys = ON` → `PRAGMA integrity_check`。

### 决定 4：backup.allCourses 遍历调用 backup.course

**依据**：07-WF §5 每课程独立 zip（便于单独恢复）。不打包为单一 zip。
**实现**：backup.allCourses 查询学期所有 course_instances，逐个调用 packCourse + 写 backup_records，返回 BackupRecord[]。
