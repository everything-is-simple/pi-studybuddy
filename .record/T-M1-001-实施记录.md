## 3. 偏差

1. **ToolDefinition 类型推断**：pi-coding-agent 的 ToolDefinition<TParams> 在返回 ToolDefinition[] 数组时，TParams 宽化为 TSchema，导致 execute 内 params: unknown。偏差处理：在 execute 内以 `params as { ... }` 类型断言解构，符合 pi docs 示例范式（examples/sdk/06-extensions.ts 同模式）。
2. **typebox 依赖**：pi 底座用 typebox（非 @sinclair/typebox），独立 npm 包 typebox@1.1.38。偏差处理：加为 dependencies，package.json + pnpm-lock.yaml 更新。
3. **SqlParams 类型新增**：node:sqlite 的 SQLInputValue 类型与 Record<string, unknown> 不兼容。偏差处理：在 src/data/sqlite.ts 新增 SqlParams 类型别名，handler 文件统一引用。

## 5. 关键决定及依据

1. **S1Context 集中管理句柄**：依据 03-Arch §6.2（数据层访问模式），handler 通过 ctx.globalDb / ctx.semesterDb(id) 访问，避免散落的 new DatabaseSync。
2. **lookup 跨库查找**：依据 05-ERD §1.3（每学期独立 semester.db），entityId 仅在学期库内唯一，需遍历非 archived 学期库定位。M1 简化：遍历查找（数据量小，无需索引）。
3. **工具 execute 薄封装 handler**：依据 03-Arch §2.2（registerTool + handler 分离），工具层只做 TypeBox schema + 参数透传 + 结果格式化，业务逻辑全在 handler。
4. **dailyBrief 纯规则聚合**：依据 03-Arch §3.1（studybuddy_daily_brief 非 AI），按 due_date <= today + status IN (pending, in_progress) 规则过滤，不调用 AI 模型。
