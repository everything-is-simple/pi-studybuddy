## 2. 实际交付

- `MaterialsTab` 按当前 `academicContext.courseId`（优先于旧 `courseId`）调用 `materials.list({ courseId })`，复用 `useTabData` 的 loading/error/empty/ready 与旧响应隔离。
- 上传通过现有 `window.piBridge.showDialog` 选择文件；main 返回一次性 `importToken/fileName/fileSize`，renderer 只把 capability 元数据交给真实 `materials.upload({ courseId, file })`，不把源文件路径交给 host；成功后触发 list 刷新，错误只显示固定中文文案。
- `pending` 调用 `materials.convert`，`conversion_failed` 调用 `materials.retryConversion`，`converted` 调用 `materials.generateNote`；按钮按状态和 busy 状态门控。
- 归档 `academicContext.isReadOnly` 阻止所有写 RPC；上下文 token 阻止对话框返回后跨课程旧写入，递增 action id 阻止旧 Promise 清理新动作。
- `src/main/ipc.ts` 的通用 open dialog 仅允许 `openFile`；renderer 图片过滤器与既有 handler 支持集合同步加入 GIF/BMP。
- main 侧对用户选择的普通文件创建一次性 staging capability；S2 host 在 `materials.upload` 中校验并消费 `importToken`，使用源文件 stat 大小，以临时文件+rename 原子复制到 `<dataRoot>/<storageKey>` 后再写 Material；转换管道随后从该 storageKey 读取。
- S2 host 的 materials/notes/modules 写 handler 统一调用 archived 学期守卫；归档仍可读，直接 RPC 写入被固定 BAD_REQUEST 拒绝。
- 新增 mounted happy-dom、handler 隔离 fixture 与真实 Electron E2E 覆盖文件导入/storage、转换读取和 host archived 写防线。

## 4. 问题及根因

- 初始 RED 曾暴露旧组件只有静态上传入口、无真实动作接线、无固定动作错误状态；当时的原始失败输出未保存到任务隔离目录，已如实列为审计缺口，不能将其当作可独立复核的 RED 日志。
- 双独立审查发现上传对话框跨课程竞态、归档只读漏门控、动作 key 复用竞态、list 刷新断言不足，以及通用 open dialog 允许目录；随后补充 host 文件导入/storage 和 archived 写守卫，并由 handler/E2E 回归覆盖。
- 文件导入/storage 缺口的根因是旧 handler 既未消费 renderer 的源文件语义，也未建立受控导入 capability；本轮改为 main staging + 一次性 token，host 增加普通文件校验、真实 stat 大小、隔离 storage 原子复制和 DB 失败清理。
- 初始 Node25 下 toolchain Node probe/manager 的 `unverified` 结果属于环境漂移；切换到 Node24.14.0 / pnpm11.20.0 后同一全量测试与 verify full 均通过，未修改无关 toolchain 代码。

## 5. 关键决定及依据

1. 不新增 RPC 方法或 schema；依据用户追加授权，修改既有 S2 handler 和 FileMeta 说明来闭合现有 upload 契约。
2. 写操作以 `academicContext.isReadOnly` 为硬门控，避免归档课程被 UI 事件写入；依据 `semester-course-state.ts` 的只读语义与 AGENTS.md §9。
3. `ContextToken` 与 action id 双重校验用于 dialog/RPC Promise 的课程切换和同 key 重入隔离；依据 T-M4-007/T-M4-008 renderer 异步门控模式。
4. 将通用 open dialog 限制为 `openFile`，不允许把目录伪装为资料；依据 S2 文件选择语义与审查结论。
5. 不把 Node25 结果冒充 Node24 质量门；用户授权后安装 Node24.14.0 并以 pnpm11.20.0 重新通过完整质量门。文件导入/storage、renderer capability transport 与 host archived 防线均有 handler fixture 和真实 Electron 证据；依据 AGENTS.md §8.4、§11.4。
6. 不向 agent-host 传递任意源路径；使用 main 签发的一次性 `importToken`，并在 `DialogResult`/`FileMeta` 中同步 capability 元数据，避免把受控导入误写成普通路径上传。
