## 4. 问题及根因

| # | 问题 | 根因 | 解决 |
|---|---|---|---|
| 1 | RED 初次 8/9 失败 | CaptureTab 为 T-M2-008 静态 UI，无 RPC/受控状态 | RED 证据留存 `H:\pi-studybuddy-tmp\runs\T-M4-017\red\red-initial-failure.log`，按 C-RED 用例实现 |
| 2 | 转写中按钮文案变为“转写中…”后测试无法匹配“开始转写” | in-flight 按钮文案切换 | 测试按“转写中…”匹配；实现正确 |
| 3 | 清空转写文本后保存区整个消失 | 渲染条件基于 transcript 非空 | 引入独立 `hasTranscription` 状态，转写成功后常驻区块，清空文本仍可编辑 |
| 4 | textarea/input 编辑不生效 | React 受控组件 value tracker：直接赋值 `value` 同步 tracker，onChange 认为值未变 | 测试用原生 value setter（`Object.getOwnPropertyDescriptor(...).set`）绕过 tracker |
| 5 | 错误净化对未知错误只显示“操作失败，请重试” | cleanError 无操作级 fallback | 增加操作级 fallback：转写 → “转写失败，请检查音频文件是否完整”；保存 → “保存失败，请重试” |

## 5. 关键决定及依据

| 决定 | 依据 |
|---|---|
| 文件获取用 desktop dialog rawPath capability（方案 A）而非 webUtils 拖拽（方案 B） | T-M4-011 importToken capability 先例；S7 `FileMeta.path` 契约注释明确本地绝对路径供 whisper.cpp 读取；webUtils 需额外 preload 暴露且无 UI 依据 |
| E2E 文件选择用 renderer 测试 seam `__PI_CAPTURE_FIXTURE__`（方案 A） | 原生 showOpenDialog 不可自动化；renderer 页面 JS 本已完全可信（可通过 piBridge 直接调 RPC），seam 仅注入 FileMeta，无权限升级；生产用户无页面 JS 注入路径 |
| 错误净化白名单 + 操作级 fallback | AGENTS.md §9.3 永不记录/展示路径/UUID/栈；07-WF §2.7 固定文案 |
| 归档防线不新增 assertSemesterWritable | S7 host `findSemesterByCourseId` 仅搜索 `deleted_at IS NULL` 活跃学期，归档学期课程查找必然 notFound——结构性防线，无需像 S5/S6 那样补丁 |
| `hasTranscription` 独立状态 | 转写结果区块在首次转写后常驻，满足 09-UI §4.10“转写结果（可编辑）”与空文本可补写 |
