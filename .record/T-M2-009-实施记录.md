## 4. 问题及根因

### 问题 1：E2E-04 mock exam generation FK 错误
**现象**：mock-exam-generator 在课程无知识模块时用 `default-module` 作为 `knowledge_module_id`，违反 FK 约束到 `knowledge_modules.id`。
**根因**：生产无"创建知识模块"RPC——模块由 S2 笔记生成 job processor 创建，E2E 不执行该 processor。
**修复**：test-main.js 新增 `test.seedModule` 测试专用 RPC，直接 SQL 插入知识模块，复用 `materials.upload` 产物满足 `material_id` FK。E2E-04 beforeAll 中先 upload material + seedModule 再 generatePaper。

### 问题 2：E2E-07 TTS 引擎切换后 speak 仍返回 sapi
**现象**：`tts.switchEngine("edge-tts")` 后 `tts.speak` 不带 engine 参数，期望返回 `engine: "edge-tts"`，实际返回 `"sapi"`。
**根因**：`createMockTtsAdapter` 的 `speak` 方法硬编码 `return { playbackId, engine: "sapi" }`，忽略了传入的 `opts.engine` 参数。
**修复**：改为 `const engine = opts?.engine ?? "sapi"; return { playbackId, engine };`。handler 层 `handleSpeak` 调用 `adapter.speak(p.text, { engine })` 总是传 engine 参数，修复后 mock adapter 正确返回对应引擎。

### 问题 3：E2E-08 backup restore FK 约束违规
**现象**：`backup.restore` 用 `create_new` 冲突解决时，子表（materials/practice_sessions 等）保留原始 `course_instance_id`，成为孤儿记录导致 FK 错误。
**根因**：zip-restorer 在导入 course_instances 时生成新 `restoredCourseId`，但未重映射子表的 `course_instance_id`。
**修复**：zip-restorer 导入子表行时检查 `row.course_instance_id === manifest.course_instance_id && restoredCourseId !== manifest.course_instance_id`，若是则重映射到 `restoredCourseId`。

## 5. 关键决定及依据

### 决定 1：保留前序会话遗留代码
**决定**：保留前序会话违规写的代码作为初始实现基线，从质量门步骤继续。
**依据**：代码本身有质量（6 E2E 文件 + 1 源码修复），直接丢弃浪费。AGENTS.md §8.2 禁止 `git stash`。保留后经完整质量门验证通过即视为有效。

### 决定 2：test.seedModule 作为测试专用 RPC
**决定**：在 test-main.js 新增 `test.seedModule` RPC 而非在生产 API 加创建知识模块方法。
**依据**：生产中知识模块由 S2 笔记生成 job processor 创建（非用户直接创建）。test.seedModule 只存在于 test-main.js（不进 dist/、不进生产代码），与集成测试直接 SQL 写入模式一致。

### 决定 3：tts-adapter mock 修复而非改测试
**决定**：修复 mock adapter 的 engine 硬编码 bug，而非修改 E2E-07 测试期望。
**依据**：handler 层 `handleSpeak` 第 68 行 `adapter.speak(p.text, { engine })` 总是传 engine 参数，mock adapter 应尊重该参数。硬编码 `engine: "sapi"` 是 bug——真实 adapter（createRealSapiAdapter/createRealEdgeTtsAdapter）都根据实际引擎返回对应值。
