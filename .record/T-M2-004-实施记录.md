## 3. 偏差

### 偏差 1：TtsContext 从单 adapter 改为双 adapter 设计

**计划**：TtsContext 注入单一 ttsAdapter，adapter 内部处理双引擎。
**实际**：改为注入 sapiAdapter + edgeTtsAdapter 两个实例，handler 层根据 engine 路由 + edge-tts 失败降级 SAPI。
**原因**：real adapter 是分开的（createRealSapiAdapter / createRealEdgeTtsAdapter），单一 adapter 接口无法清晰表达降级逻辑。双 adapter 设计更符合 03-Arch §3.3 外部桥契约（每个外部桥独立 Adapter）。
**影响**：无负面，设计更清晰，降级逻辑在 handler 层显式可控。

### 偏差 2：TtsAdapter 五实现（计划三实现）

**计划**：mock/failing/real 三实现。
**实际**：mock/failing/failingEdge/realSapi/realEdgeTts 五实现。
**原因**：08-Test §3.5 断言 2"edge-tts 失败降级 SAPI"需要专门测试用 failingEdge adapter（engine=edge-tts 抛错，engine=sapi 返回 fallbackUsed=true）。
**影响**：无负面，测试覆盖更完整。

### 偏差 3：tools.ts switchEngine execute 改为 async

**计划**：switchEngine execute 同步（handler 是同步）。
**实际**：改为 async（因 ToolDefinition.execute 契约要求返回 Promise）。
**影响**：无负面，符合 pi 底座 ToolDefinition 契约。

## 4. 问题及根因

### 问题 1：tts.ts 语法错误（TS1144）

**现象**：`): (params: unknown) => void => {` 被 TS 解析器误判。
**根因**：返回函数类型的箭头函数，返回类型 `(params) => void` 后跟 `=> {` 造成歧义。
**修复**：移除返回类型后的 `=> {`，改为 `): (params: unknown) => void {`（函数声明语法）。

### 问题 2：tts-tools.test.ts 缺少 beforeAll import

**现象**：`ReferenceError: beforeAll is not defined`。
**根因**：测试文件只 import了 describe/it/expect，遗漏 beforeAll。
**修复**：补充 beforeAll import。

### 问题 3：MOCK-08 duration 断言写错

**现象**：`expected 1000 to be 500`。
**根因**：断言注释写"10 字 * 50ms = 500ms"但实际 mockDuration 有 `Math.max(1000, ...)` 下限，d2 应为 1000 不是 500。
**修复**：断言改为 `expect(d2).toBe(1000)`。

## 5. 关键决定及依据

### 决定 1：SAPI real adapter 用 powershell 子进程（决策点 1）

**依据**：03-Arch §3.3 外部桥契约（子进程调用）+ 零 npm 依赖（powershell 是 Windows 自带）。
**实现**：`spawn("powershell.exe", ["-NoProfile", "-NonInteractive", "-Command", "Add-Type -AssemblyName System.Speech; ..."])`。

### 决定 2：edge-tts real adapter 用 CLI 子进程（决策点 2）

**依据**：03-Arch §3.3 外部桥契约（CLI 路径只来自配置，不猜路径）。
**实现**：`spawn(edgeTtsCliPath, ["--text", text, "--write-media", "/dev/null"])`，路径为空时 INTERNAL_ERROR + 固定文案。

### 决定 3：契约微调 api.ts tts.speak result 扩展（决策点 4）

**依据**：权威链 08-Test（优先级4）> api.ts 现状（优先级7）。08-Test §3.5 断言 `r.fallbackUsed` 和 `r.engine`，但 api.ts 现状只有 `{ playbackId }`。
**实现**：扩展为 `{ playbackId, engine: "sapi" | "edge-tts", fallbackUsed?: boolean }` + types.ts 补 TtsSpeakResult 接口。
