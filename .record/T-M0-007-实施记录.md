## 3. 偏差

### 3.1 pi 底座版本：0.84.0 → 0.80.10

**计划**：安装 `@earendil-works/pi-coding-agent@0.84.0` + `@earendil-works/pi-ai@0.84.0`（与参考仓库 H:\pi-references\pi 本地版本一致）。

**实际**：安装 `0.80.10`（pi-desktop 当前使用的版本）。

**原因**：0.84.0 / 0.84.1 npm 包发布缺陷——`node_modules/@earendil-works/pi-coding-agent` 缺少 `dist` 目录（仅含 package.json + README + docs，无编译产物 + 类型声明），导致 `import { ExtensionFactory } from "@earendil-works/pi-coding-agent"` 类型解析失败。0.80.10 经验证 dist 目录完整（index.js + index.d.ts 齐全）。

**影响**：版本号低于计划，但 ExtensionFactory / ExtensionAPI / ToolDefinition 类型契约在 0.80.10 与 0.84.0 一致（扩展接口稳定），不影响空壳类型化对接。pnpm-workspace.yaml 补 `minimumReleaseAgeExclude` 排除 pi 0.84.0 以防未来误升级。

**依据**：pi-desktop package.json:47-48 使用 `0.80.10` 固定版本（权威范式）。

### 3.2 类型命名：PiExtension → ExtensionFactory

**计划（03-Arch §2.1 伪代码）**：`createStudyBuddyExtension(): PiExtension` 返回 `{ name, setup(pi) }` 结构。

**实际**：`createStudyBuddyExtension(): ExtensionFactory` 返回 `async (pi: ExtensionAPI) => { ... }`（inno-agent createInnoExtension 范式）。

**原因**：pi 底座无 `PiExtension` 类型——实际扩展工厂类型为 `ExtensionFactory = (pi: ExtensionAPI) => void | Promise<void>`（pi types.ts:1518）。03-Arch §2.1 伪代码的 `PiExtension { name, setup(pi) }` 是设计文档命名与实现的偏差，核心意图"单一扩展工厂"不变。

**影响**：扩展名通过 `STUDYBUDDY_EXTENSION_NAME` 常量导出（供未来 pi 启动 Extensions 列表显示名使用），setup 函数本身即为 ExtensionFactory 签名。不偏离 03-Arch §2.1 权威意图。此偏差未修改 03-Arch（设计文档已审查批准，类型名以 pi 底座契约为准），在源文件注释中说明。

### 3.3 pnpm-workspace.yaml allowBuilds 补全

**计划**：未提及 pnpm-workspace.yaml 修改。

**实际**：补 `allowBuilds: { '@google/genai': false, protobufjs: false }` + `minimumReleaseAgeExclude` 排除 pi 0.84.0。

**原因**：pnpm 11 对未配置 allowBuilds 的构建脚本包会报 `ERR_PNPM_IGNORED_BUILDS` 退出码 1。pi-coding-agent 传递依赖 `@google/genai` + `protobufjs` 有构建脚本，需显式声明忽略。`minimumReleaseAgeExclude` 防 pnpm release-age 策略拒绝 0.84.0（虽已降级，保留排除以防未来）。

**影响**：pnpm install 不再报错，依赖安装稳定。

## 4. 问题及根因

### 4.1 pi 0.84.x npm 包缺 dist 目录

**现象**：`pnpm add @earendil-works/pi-coding-agent@0.84.0` 后，`node_modules/@earendil-works/pi-coding-agent` 无 dist 目录，`import { ExtensionFactory }` 类型解析失败，tsc 报 `Cannot find module`。

**根因**：0.84.0 / 0.84.1 npm 包发布缺陷——`prepublishOnly` 脚本（`npm run clean && npm run build && npm run shrinkwrap`）可能未完整执行，或 `files` 字段过滤异常，导致 dist 未包含在发布的 tarball 中。

**修复**：降级到 0.80.10（pi-desktop 验证可用的版本），dist 完整。

### 4.2 pnpm install 退出码 1（ERR_PNPM_IGNORED_BUILDS）

**现象**：`pnpm add` 失败，退出码 1，提示 `@google/genai` + `protobufjs` 构建脚本被忽略。

**根因**：pnpm 11 默认拒绝运行未在 `allowBuilds` 显式声明的构建脚本。

**修复**：pnpm-workspace.yaml `allowBuilds` 补 `@google/genai: false` + `protobufjs: false`（显式忽略）。

## 5. 关键决定及依据

### 5.1 pi 底座作为 dependencies（非 peerDeps）

**决定**：`@earendil-works/pi-coding-agent` + `@earendil-works/pi-ai` 作为 `dependencies`（固定版本 `0.80.10`，非 `^`，非 peerDeps）。

**依据**：pi-desktop package.json:47-48 权威范式（dependencies 固定版本）。单机单用户桌面应用无需 peerDeps 共享单例，dependencies 确保版本隔离与可复现构建。

**修正**：04-Todo §4.1 看板原标记 "pi（npm peerDeps）" → "pi（npm dependencies）"（v0.1.10 已修正）。

### 5.2 空壳采用 ExtensionFactory 类型（非 PiExtension）

**决定**：`createStudyBuddyExtension(): ExtensionFactory`，返回 `async (pi) => {...}`。

**依据**：pi 底座实际类型 `ExtensionFactory = (pi: ExtensionAPI) => void | Promise<void>`（types.ts:1518）。inno-agent `createInnoExtension()` 范式一致。03-Arch §2.1 的 `PiExtension` 为伪代码命名，核心意图"单一扩展工厂"不变。

### 5.3 空壳不接入 agent-host 运行时加载

**决定**：T-M0-007 仅创建工厂文件 + 类型契约验证，不在 agent-host/index.ts 装配 pi 运行时加载。

**依据**：03-Arch §6.7 会话管理是后续任务（M1+）。agent-host 当前是 RPC 服务，不加载 pi 扩展。空壳的"集成测试"验证类型契约对接（`const factory: ExtensionFactory = createStudyBuddyExtension()` 编译时对接），非运行时加载。
