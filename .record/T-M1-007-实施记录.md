## 4. 问题及根因

- **mammoth 类型不匹配**：`extractRawText` 参数类型与 @types/node Buffer 泛型冲突。根因：mammoth 的 Input 类型泛化。修复：显式类型断言 `as unknown as (b: Buffer) => Promise<{ value?: string }>`。
- **S2Context 命名冲突**：私有字段与 getter 同名触发 TS2300（duplicate identifier）。修复：私有字段改为 `textExtractorAdapter`，保留公开 getter `textExtractor`。
- **测试文件位置不被 vitest 识别**：初始测试放 src/ 未被 test runner 收集。修复：移至 `tests/unit/agent-host/s2/`（遵循既有 WPS/OCR 测试约定）。
- **集成测试注释终止符**：注释含 `*/` 导致 TS 解析错误。修复：将 `convert_*/ocr_image` 改为显式列举 `convert_pdf/convert_docx/convert_pptx/convert_xlsx/ocr_image`。
- **重复 convert 状态机断言**：对已转换材料二次 convert 失败。修复：更新测试断言为"状态机正确拒绝非 pending/conversion_failed 材料的转换"。

## 5. 关键决定及依据

- **TextExtractor 三态可注入**：mock（默认）/failing（失败路径）/real（真实库），复用 OcrAdapter/WpsAdapter 既有模式，tests 通过注入控制行为。依据 03-Arch §3.3 + AGENTS.md §6.4 薄 Adapter。
- **进程内 Node 库提取**：pdf-parse/jszip/mammoth 在主进程内完成文本提取（非外部子进程），与 OCR/WPS 的 Python/COM 子进程桥区分——文本提取无崩溃隔离需求，走进程内更薄。依据 03-Arch §5.3。
- **normalized_texts 先删后插**：UNIQUE(material_id) 约束下保持幂等（ref materials.replaceText 既有语义）。依据 05-ERD §3.2.2。
- **未注入 adapter 维持"仅登记 Job"语义**：与 wps_convert/T-M1-006 一致，注入 mock 后才走真实路径，不破坏既有测试。依据 07-WF §2.3 + 03-Arch 延后执行。
- **错误固定文案**：MSG_NOT_CONFIGURED / MSG_EXTRACT_FAILED 均固定，不泄漏路径/stdout/stderr/密钥。依据 03-Arch §3.3 + 08-Test §3.3.2 + AGENTS.md §9.3。
- **合成夹具驱动真实单件**：jszip 构建最小 OOXML + 受控 pdf，符合 AGENTS.md §5.4（集成/E2E 用 mock，单件可用受控夹具）。
