## 3. 偏差

### 3.1 OCR 不装配进 S1 RPC 路由，仅经工具暴露

**计划**：`src/agent-host/handlers/s1/index.ts` 装配 handleOcrSchedule 到 S1 handler 路由

**实际**：`s1/index.ts` 未修改，OCR 仅经 `studybuddy_ocr_schedule` 工具暴露

**原因**：计划 §3 注已预判此决策——OCR 是 S1 内部能力，03-Arch §3.4 工具表 `studybuddy-ocr-schedule` 独立暴露（课程表 OCR 识别预览），无独立 RPC 方法。工具 execute 直接调 `handleOcrSchedule`，不占用 RPC 路由。此为用户授权范围内实现决策。

### 3.2 pytest 单件走真实 RapidOCR（非 skip）

**计划**：若 venv 未探测到 RapidOCR 则在测试中标注 skip

**实际**：OCR venv 已含 RapidOCR/onnxruntime/PIL，7 格式真实识别全通过（08-Test §11.2 表"OCR venv 单件真实"）

## 4. 问题及根因

### 4.1 pytest 未安装于 OCR venv

**现象**：`python -m pytest` 报 ModuleNotFoundError

**根因**：OCR venv 仅含 OCR 依赖，未装 pytest

**修复**：`python -m pip install pytest` 安装到 venv

### 4.2 PIL 保存 JPG 缺格式映射

**现象**：`img.save(path, fmt)` 对 "jpg" 报 KeyError

**根因**：PIL 保存格式名必须用 "JPEG" 而非 "jpg"

**修复**：测试中 `_SAVE_FORMAT` 字典将 "jpg"→"JPEG"

### 4.3 测试导入路径层级错误

**现象**：`ocr-adapter.test.ts`/`ocr.test.ts`/`tools-s1-ocr.test.ts` 相对导入无法解析

**根因**：目录层级为 4 层（从 tests/ 到 src/），原写 3 层 `../../` 不足

**修复**：改用 `../../../../` 4 层相对导入

## 5. 关键决定及依据

### 5.1 OCR 独立工具暴露，不并入 RPC 路由

**决定**：`studybuddy_ocr_schedule` 作为独立 registerTool，execute 薄封装调 handleOcrSchedule

**依据**：
1. 03-Arch §3.4 工具表 `studybuddy-ocr-schedule` 独立暴露（学生对话中预览 OCR 识别结果）
2. 06-API 无 OCR 独立 RPC 方法（OCR 是 S1 内部能力）
3. 计划 §3 注已授权此实现决策

### 5.2 OcrAdapter 三态可注入（参照 WhisperCppAdapter 范式）

**决定**：mock（确定性）/failing（抛错）/real（spawn Python 桥框架）三态

**依据**：AGENTS.md §5.4 mock 先于真实；TS 测试全 mock，Python 单件走真实；错误隔离验证

### 5.3 错误固定文案，不泄漏路径

**决定**：图片不存在 → BAD_REQUEST"图片不存在"；识别失败 → INTERNAL_ERROR"OCR 识别失败，请检查图片文件是否完整"

**依据**：08-Test §3.3.3 关键约束 + AGENTS.md §9.3 日志脱敏（路径属敏感信息）
