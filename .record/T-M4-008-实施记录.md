## 2. 实际交付

### 2.1 统一数据生命周期

新增 `src/renderer/components/tabs/useTabData.ts`，统一提供：

- `idle`：无 RPC 或无有效上下文；
- `loading`：请求进行中；
- `error`：请求失败，界面只显示固定中文文案；
- `empty`：请求成功但结果为空；
- `ready`：请求成功且有数据。

实现 requestId、effect cleanup、RPC client/key 代际检查和 render 阶段旧数据阻断。

### 2.2 Tab 接线

- `HomeTab`：`tasks.dailyBrief({ semesterId })`；
- `MaterialsTab`：`materials.list({ courseId })`；
- `NotesTab`：`modules.list({ courseId })`；
- `PracticeTab`：`practice.listSessions({ courseId })`；
- `MistakesTab`：并行读取 `mistakes.list` 与 `weakPoints.list`；
- `ReportTab`：`reports.list({ semesterId })`；
- `CramTab`、`CaptureTab`、`ChatTab` 补齐 `academicContext` 类型入口，但不伪造 `assessmentAttemptId`，也不在无文件时发起转写请求。

### 2.3 异步保护

- AppShell 会话搜索增加 requestId/cancelled 保护；
- ChatTab agent 事件订阅、sessions、models、modelsConfig、materials 读取增加卸载/切换保护；
- ChatTab 资料读取限制为有效 `courseId`，避免无上下文调用 `materials.list({})`。

## 4. 问题及根因

- 问题：数据型 Tab 原先主要依赖外部静态 props，AppShell 切换上下文后没有统一的数据读取生命周期。
  - 根因：Tab 缺少统一的 RPC 数据状态抽象和上下文代际标识。
  - 处理：新增 `useTabData`，以 `key + rpc client + requestId + cleanup` 管理请求生命周期。
- 问题：ChatTab 与 AppShell 会话搜索存在异步结果回写风险。
  - 根因：旧请求完成时没有检查当前请求代际或组件是否仍挂载。
  - 处理：补充 cancelled/requestId 保护和订阅清理。
- 问题：无课程上下文时资料选择器会调用空参数资料列表。
  - 根因：原 effect 只检查 RPC 和 picker 状态，未绑定课程上下文。
  - 处理：增加有效 `courseId` 门禁。
