## 4. 问题及根因

- **node:sqlite 无法被 vite-node/esbuild 解析**：`import { DatabaseSync } from "node:sqlite"` 在 vitest transform 阶段报 "Failed to load url sqlite"。根因：`node:sqlite` 是 Node 22.5+ 实验性内置模块，esbuild 内置模块白名单未收录，transform 时剥离 `node:` 前缀后按普通模块 `sqlite` 解析失败；`deps.optimizer.ssr.exclude` 无法阻止该 transform。
- **DatabaseSync 同名值/类型冲突**：db.ts 等把 `DatabaseSync` 既当构造器（值）又当实例类型用，仅导出值导致 `TS2749: 'DatabaseSync' refers to a value`。根因：sqlite.ts 未同时导出同名类型。
- **测试 fixture 缺审计列/外键父行**：多表 INSERT 未提供 NOT NULL 无默认的 `created_at`/`updated_at`，且引用外键无父行，触发 NOT NULL/FK 约束失败。根因：初始 fixture 未按表结构补全。
- **`:memory:` 库 WAL 断言失败**：PRAGMA-01 在内存库断言 journal_mode == wal 得到 memory。根因：WAL 仅对持久化文件库生效。
- **SEMESTER-02/03 共享 db 的 id 冲突**：同一 semester describe 的 beforeAll 共享一个 db，两用例插入相同 course_instances id 'c1' 触发 UNIQUE 冲突。根因：用例间未隔离 fixture id。

## 5. 关键决定及依据

- **采用 `process.getBuiltinModule("node:sqlite")` 动态加载**：替代字面 `import`，运行时（Electron 主进程 / vitest）均原生解析内置模块，编译期用 `import type` 保留强类型（esbuild 擦除 type-only import）。依据：Node v22.16 支持（22.3+），且不引入 native 依赖，符合 05-ERD §1.1 node:sqlite 权威条款。
- **sqlite.ts 同时导出同名值 + 类型**：`export const DatabaseSync`（构造器）+ `export type DatabaseSync`（实例类型），满足消费者既 `new DatabaseSync()` 又 `db: DatabaseSync`。依据：TS 值/类型双命名空间声明合并。
- **memory 目录以 `dir/memory/...` 落地**：符合 05-ERD §4 "业务数据根目录（memory 的父级）"，memory 作为数据根下的子目录。依据：05-ERD §4 权威条款。
- **审计列保持 NOT NULL 无默认**：05-ERD §3 明确 `created_at`/`updated_at` TEXT NOT NULL（ISO 8601 UTC），不改 schema 加默认值，测试 fixture 显式提供。依据：05-ERD §3 权威条款 + AGENTS.md §2 权威链（不静默偏离已批准设计）。
- **PRAGMA-01 改用文件库验证**：WAL 语义只对持久化库成立，用隔离目录文件库验证 journal_mode == wal。依据：05-ERD §9 WAL 用途。
